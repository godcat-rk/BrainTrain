# BrainTrain v2 方針書（2026-07-13 決定）

現状把握は [status-2026-07.md](status-2026-07.md) を参照。
本書は 2026-07-13 セッションでの議論に基づくプロダクト方針・技術選定の記録。

---

## 1. プロダクトビジョン（オーナーの構想）

- **本格的なプロダクト化**を目指す。プロトタイプ（GitHub Pages 版）で想定以上の手応えを得たため
- **iOS 市場を最優先**。日本語＋英語の2言語で展開
- 市場仮説: ドーパミン中毒・ブレインフォグへの社会的関心の高まり × 「継続的にスコアを可視化しながら、通信や制約なしに楽しく脳トレできる」体験 → 脳トレ需要は伸びる。本気で狙いに行く
- **運用コスト極小・サーバー費0**がアーキテクチャの大原則。プロトタイプでローカル完結の成立を確認済み

## 2. 決定事項

### 2.1 開発環境・前提（確定）

| 項目 | 決定 |
|---|---|
| 開発機 | **Mac を使用**（所有済み。必要なら新調も可）。Windows で無理をする線は捨てる |
| 実機 | iPhone 所有済み → TestFlight で実機確認 |
| Apple Developer Program | $99/年 を許容。ストア公開の唯一の固定費 |
| 学習コスト | React Native の学習を受け入れる |

### 2.2 技術スタック（確定）

**Expo (React Native) + TypeScript** を採用する。

**選定理由（経緯を残す）:**

1. **コーディングエージェント（Claude Code）の得意領域**であること — オーナーが明示した選定基準。TypeScript/React はエージェントが最も速く正確に書ける言語圏で、検証ツールも headless で回しやすい
2. **既存資産の直接移植**: ゲームロジックのフック3本（約670行）は React 共通仕様のため変換なしで動く。SwiftUI だとロジックも全部書き直し
3. **Mac × Expo は最速の開発ループ**: iOS シミュレータ上でエージェントが「ビルド→起動→スクショ→修正」を秒単位で自走できる
4. **運用コスト思想との一致**: EAS Update により JS のみの修正を審査なしで配信可能。Android 展開も将来ほぼ追加コストなしで可能
5. SwiftUI ネイティブ案は「最高の質感」と引き換えにロジック再実装・単一プラットフォーム化・エージェント生産性低下を招くため不採用。Flutter は資産全捨てになるため不採用

**主要ライブラリ想定**（着手時に最新を再確認すること）:

| 用途 | 候補 |
|---|---|
| ルーティング | Expo Router |
| ローカルDB | expo-sqlite（PlayRecord 汎用スキーマ思想は v1 から継承） |
| i18n | expo-localization + i18next（ja / en） |
| グラフ | victory-native 等（recharts は Web 専用のため置換） |
| 広告 | react-native-google-mobile-ads（AdMob） |
| E2E | Maestro（Playwright のシナリオ設計を流用） |
| ビルド/配信 | EAS Build + EAS Submit → TestFlight |

### 2.3 アーキテクチャ原則（確定）

1. **ローカル完結・サーバー費0**: スコアは端末内 DB、広告はクライアント直、i18n もクライアント側
2. **プライバシーを売りにする**: 「データは端末から出ない・通信不要・追跡なし」をデジタルウェルネス文脈の訴求点として明示的に打ち出す（コスト削減の副産物ではなく製品価値として扱う）
3. ロジック（フック）と UI の分離を v1 から継承。ゲーム追加時にスキーマ変更不要の汎用 PlayRecord も継承

### 2.4 マネタイズ方針（確定＋設計指針）

- **まず広告（AdMob）**で開始
- ただし「ドーパミン中毒対策を掲げるアプリに広告」という思想矛盾を突かれるリスクがあるため、**「買い切りで広告除去」の IAP を最初から設計に組み込む**（実装は広告導入後でよいが、UI/コード構造上の置き場を確保しておく）
- ストア審査対策: 医学的効能（「脳が治る」「症状が改善」等）の表現は使わない

## 3. 移植マップ

| v1 資産 | v2 での扱い |
|---|---|
| `src/games/*/use*.ts`（フック3本） | **そのまま移植**。useNbackGame の lint エラー2件はこの機会に修正 |
| ゲーム仕様・調整値（N-back 一致確率45%・表示2.6秒等の試行錯誤の結果） | そのまま継承。最重要資産 |
| PlayRecord 汎用スキーマ | 継承（Dexie → expo-sqlite） |
| Playwright E2E のテストシナリオ設計 | Maestro で書き直し（シナリオは流用） |
| Tailwind UI・recharts ダッシュボード | 書き直し（デザイン刷新とセット） |
| android/・Capacitor・Docker・GitHub Pages 設定 | 捨てる。Pages 版はデモとしてそのまま放置 |

## 4. マイルストーン（たたき台）

- **M0: 環境構築** — Mac 開発環境（Xcode / Node / Expo / Claude Code）、新リポ作成、Expo プロジェクト scaffold、Apple Developer 登録
- **M1: 縦に1本通す** — コルシ移植＋日英 i18n＋ローカル保存＋**TestFlight 配信**。ここが最初のゴール。これが通れば以降は量産フェーズ
- **M2: 横展開** — 神経衰弱・N-back 移植、ダッシュボード（グラフ）再構築
- **M3: 製品化** — デザイン本格刷新、AdMob 導入、プライバシーポリシー、App Store 審査提出
- **将来**: 広告除去 IAP、新ゲーム追加、Android 展開（Expo なら低コスト）

## 5. v1（本リポ）の扱い

- 「プロトタイプ v1」として凍結。status レポートの分類 A（残骸: PNG・マージ済みブランチ・テンプレ残骸等）を掃除してから保存
- GitHub Pages 版は無料デモとして存置（追加投資はしない）
